# TikTok через Zen

Рабочее подключение e-content с 17 ноября 2026 года. Авторизация остаётся в обычном профиле Zen. Расширение Firefox WebExtensions исполняет ограниченные задания локального цеха; Node не запускает браузер для входа и не получает cookies, пароль или код TikTok.

## Подключение

При локальной разработке можно загрузить `extensions/zen-tiktok/manifest.json` непосредственно из проекта вместо ZIP. Это тот же ID расширения и то же подключение; дальнейшие правки подхватываются кнопкой «Обновить» в `about:debugging`.

1. В e-content открыть «Источники → TikTok → Аккаунт», скачать `e-content-zen.zip`.
2. В Zen открыть `about:debugging#/runtime/this-firefox`, загрузить ZIP через «Загрузить временное дополнение».
3. Получить код кнопкой «Подключить Zen», вставить его в окно расширения e-content.
4. Дождаться определения аккаунта и роликов. Выбрать последние 10 или 20, запустить участок TikTok или весь цикл.

Это временная установка: после перезапуска Zen её нужно повторить. Идентификатор расширения постоянный, собственный токен хранится в extension storage. Для обычной постоянной установки необходима подпись Mozilla; отключение проверки подписей не требуется и не предлагается.

Zen должен оставаться запущенным. Сбор создаёт отдельную вкладку, по возможности дублируя уже открытую вкладку TikTok, чтобы наследовать браузерный контекст. Исходная вкладка пользователя не изменяется. Если пользователь работает в разных контейнерах, выбирается активная либо недавно открытая вкладка TikTok. Расширение проверяет фактический аккаунт перед каждой задачей и останавливается при его смене.

## Модули

- `server/tiktok/connection-model.ts`: общее состояние подключения, серверная выборка и собственный источник. Оба транспорта используют одну модель настроек, но разные ключи хранилища.
- `server/tiktok/zen-bridge.ts`: pairing, привязка токена к origin установки, очередь одной задачи, heartbeat, ограничение длительности, отмена и отклонение запоздавших сообщений.
- `server/tiktok/zen-account.ts`: проверка личности, нормализация и проверка присланных данных, дедупликация и лимиты; реализует обычный контракт TikTokReader. Цех и библиотека не зависят от браузерного транспорта.
- `extensions/zen-tiktok/background.js`: получение задач, отдельная вкладка, последовательное чтение страниц и наблюдение за ответами TikTok.
- `extensions/zen-tiktok/content.js`: фиксированные действия только на TikTok: чтение метаданных, открытие и прокрутка комментариев, раскрытие ответов. Произвольный JavaScript от сервера не исполняется.
- `server/extension-package.ts`: ZIP из фиксированного списка файлов расширения. В пакет не входят `.local`, сессии или конфигурация пользователя.

Предыдущий Edge/Playwright-адаптер сохранён для изолированных проверок. Рабочий сервер по умолчанию создаёт ZenTikTokAccount. Явный тестовый `tiktokContextFactory` выбирает прежний адаптер; скрытого автоматического переключения к отдельному браузеру нет.

## Доступ

Локальная форма по-прежнему использует Host/Origin, HttpOnly local-session и CSRF. Маршруты `/api/zen-bridge/{pair,poll,event}` имеют отдельный контракт: только origin `moz-extension://…`, собственный заголовок origin установки и bearer-токен. Если HTTP Origin присутствует, он должен совпадать с заявленным origin. Firefox может не ставить Origin для привилегированного запроса расширения; в этом случае обязательны заголовок установки и секрет. Обычным сайтам доступ закрыт независимо от знания токена.

Pairing запускается только из защищённой формы e-content: 12 шестнадцатеричных символов, срок 5 минут, максимум 5 попыток. Код одноразовый. Токен 256 бит хранится в локальном vault зашифрованным; браузер получает только свой токен, а не данные других подключений. Переподключение меняет токен; отключение отзывает его и сохраняет собранные записи.

Разрешения расширения: storage, webRequest, webRequestBlocking, TikTok и loopback HTTP. Разрешений cookies, history, downloads, nativeMessaging и доступа ко всем сайтам нет. Наблюдение за ответами применяется только к вкладке текущего задания и только к известным маршрутам роликов/комментариев. Поток ответа без изменения передаётся сайту; сохраняемый ответ ограничен 5 МБ.

## Сбор и пределы

Личность определяется из свежего состояния вошедшего пользователя либо успешного ответа account-info. Автор посещённого ролика не считается вошедшим пользователем. Нет подтверждённой личности — нет собственного источника и успешного статуса.

Список роликов берётся из ответов страницы и серверных метаданных, сортируется по дате публикации; закреплённые старые ролики не должны вытеснять последние. Неизвестная дата и неполная выдача обозначаются как неполное покрытие. Настройки периода и фильтры комментариев применяет существующий серверный исполнитель.

Комментарии получаются из фактических ответов страницы после открытия/прокрутки обсуждения. Ответы раскрываются только если включены в настройках. Нет подписывания частных API, обхода CAPTCHA, автоматической отправки кодов или платного fallback. Пустой/нечитаемый ответ не означает ноль комментариев. Полнота ответов проверяется по доступным счётчикам; при недоступных ветках результат частичный.

Каждая навигация и известный запрос данных сборщика получает разрешение через общий бюджет цеха. Статические ресурсы и фоновая работа сайта вне вкладки задания не считаются запросами сборщика. Ограничения числа роликов/комментариев проверяются повторно сервером; неизвестные типы событий, другой ролик, другая личность и устаревший ID задания отклоняются.

Связь считается активной после heartbeat за последние 15 секунд. Потеря heartbeat задания на 20 секунд или длительность свыше 15 минут завершают задачу ошибкой с сохранением уже принятых записей. После перезапуска сервера незавершённый запуск не возобновляется скрытно: расширение отбрасывает старую задачу и ожидает нового явного запуска.

## Проверки

Версия 0.1.3 наблюдает ответы только для текущего этапа: список роликов на экране профиля либо комментарии текущего ролика. Фильтр ответа подключается синхронно до ожидания разрешения бюджета, а обработчики предыдущего документа отделены счётчиком переходов. Ошибки побочного фильтра не превращаются в ошибку всего задания; если основной ответ действительно не получен, результат не отмечается успешным. `zen-response-filter.test.ts` закрепляет эти границы, а `ZEN_TEST_CANCELLED=1 npm run check:zen` проверяет в Zen отменённый побочный запрос вместе с успешным сбором.

Обработчик `StreamFilter.onerror` сообщает о проблеме фильтра (например, недействительном ID запроса), а не является признаком блокировки аккаунта или разрыва сети со стороны TikTok: [контракт Mozilla](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/StreamFilter/onerror).

Версия 0.1.2 вызывает фиксированные действия страницы через результат `tabs.executeScript`, без `tabs.sendMessage` между сборщиком и страницей. Скрипт подключается по абсолютному пути пакета `/content.js`, заново перед каждым действием. Ошибки смены документа допускают максимум три попытки, отсутствие разрешения проверяется отдельно и не маскируется как успешный сбор. В heartbeat передаётся версия расширения, в ошибке — этап без URL, cookies и содержимого пользователя. Эти метаданные доступны в статусе подключения для диагностики устаревшей установки.

`server/tests/zen-page-access.test.ts` проверяет временную ошибку `Missing host permission for the tab`, настоящий отказ в разрешении и ограничение повторов. Проверка `check:zen` запускает обновлённую связь со страницей в настоящем отдельном профиле Zen/Firefox на изолированных ответах TikTok.

- `npm run check:server`: security, отдельный pairing, собственный источник без ручных ссылок, выбор 10/20, дедупликация, бюджеты, отмена и сохранность записей.
- `npm run check:zen`: установка настоящего ZIP и работа расширения в отдельном профиле Firefox. `FIREFOX_BIN` позволяет выбрать установленный Zen. Проверки не используют основной профиль пользователя.
- Прежние проверки Telegram и TikTok адаптеров сохранены.

Успешный тест на изолированных ответах не доказывает доступность конкретного аккаунта или неизменность интерфейса TikTok. Проверка пользовательского аккаунта выполняется после ручной установки расширения. Снимки счётчиков сохраняются с записями; исторические ряды страницы аналитики пока не заменены реальными данными.

Основания: [расширения Zen](https://docs.zen-browser.app/user-manual/extensions), [потоки ответов Firefox](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/filterResponseData), [временная установка Mozilla](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/).
