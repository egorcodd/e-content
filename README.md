# e-content · дизайн-система

Одна страница с вариантами компонентов будущей аналитической системы для авторского IT-блога. Название закреплено: **e-content**. Работа изолирована в `content-manager`.

## Запуск

Из этой папки запустите `start.cmd`. Скрипт найдёт npm в стандартной папке Windows, при необходимости установит зависимости и поднимет сайт.

```powershell
npm ci --workspaces=false
npm run dev
```

Адрес: http://127.0.0.1:5186/. Нужен Node.js 24 LTS. Зависимости и lockfile находятся в этой папке.

## Разделы галереи

- **Элементы:** кнопки с подсветкой под курсором, пружинным нажатием и движением иконок; кнопка «удержать для удаления»; переключатели со скользящей подложкой; поиск, фильтры, диалоги. Пять статусов («Ожидание», «В работе», «Готово», «Пауза», «Ошибка») — у каждого своя анимация, клик повторяет её; цепочка выполнения показывает переходы между статусами.
- **Цех:** изометрическая 3D-сцена с тремя материалами моделей: «Дымка» (по умолчанию), «Контур» и «Сетка». Приглушённые прозрачные оболочки и тонкие полупрозрачные основания без объёмного освещения и контактных теней. Переключение материала сохраняет камеру, выбранный участок и текущий процесс. Запуск участка, полный цикл, остановка и экспорт Markdown. Three.js загружается отдельным чанком; плиточный пульт используется только при недоступном WebGL или ошибке сцены.
- **Библиотека:** полупрозрачные объёмные папки и коллекции. При открытии папка плавно переходит в шапку, содержимое появляется отдельными листами с фрагментом текста и датой; возврат восстанавливает фокус на папке. Высота блока, поиск и сортировка меняются плавно. В пустую папку можно добавить демоматериал. Просмотр материала, Markdown и скачивание работают.
- **Графики:** «Динамика» с KPI и изменением к прошлому периоду, цветными рядами, подсказкой и датой под курсором, таблицей; «Путь к материалу» — конверсия публикаций в материалы по источникам; кольцевая «Структура»; «Источники» с анимацией появления и счётчиками; «Журнал сбора» — лента сессий сбора.
- **Типографика:** Inter (по умолчанию, с оптическим размером), Golos и Manrope; шкала размеров 12–40; три варианта знака — «Разрез», «Слой», «Модуль». Выбор шрифта и знака сохраняется в браузере. Токены скачиваются в JSON.

Основа палитры — чёрная и белая. Цвет несёт смысл: источники (Telegram `#3987e5`, TikTok `#d55181`, третий `#c98500`) и статусы (ожидание, работа, готово, пауза, ошибка). Цвета источников проверены на различимость, в том числе для дальтонизма; статусы всегда идут с иконкой и подписью. Базовый текст — 16 px, подписи элементов — 14 px, второстепенный текст — от 12 px на настольном экране. Анимации учитывают reduced motion; у интерактивных элементов есть клавиатурное управление и видимый фокус.

## Границы этапа

Показатели и материалы демонстрационные. Проигрывание процесса не запрашивает Telegram, TikTok или модели. Экспорты действительно создают файлы.

Серверное хранилище Markdown, авторизация, реальный сбор и MCP ещё не подключены. Эта галерея предназначена для выбора деталей, из которых затем будет собираться приложение.

«Журнал сбора» в аналитике пока использует отдельный статичный набор сессий: он не связан с запуском цеха и выбранным периодом графика. Его возможное продуктовое назначение — история запусков: источник, время, результат, ошибки и созданные Markdown-файлы. Текущие длительности и паузы этого не показывают; дальнейшее направление — история выполнения рядом с цехом, а не показатель эффективности контента.

## Исходники и проверка

`src/LabApp.tsx` — оболочка галереи, компоненты и типографика. `src/lab/` — цех, библиотека, графики, общие элементы и стили.

```powershell
npm run build
npm run check:ui
npm run check:scenarios
npm run check:library
npm run format:check
```

`build` создаёт статический сайт в `dist`. `check:ui` запускает сценарии из `scripts/check-lab.mjs` в установленном Microsoft Edge (или в браузере из переменной `CHROME_PATH`); сайт перед проверкой должен быть запущен. Для просмотра сборки используйте `npm run preview`, предварительно освободив порт 5186.

## Поведение библиотеки и меню

Выпадающие списки сортировки и фильтров используют общий компонент `Select`: тёмное меню, отметка выбранного пункта, стрелки, Home/End, Enter, Escape, закрытие снаружи и расположение в пределах окна. Иконки площадок в фильтрах монохромные, одного размера и начертания. Переходы библиотеки, диалоги, переключение сценариев и меню учитывают настройку reduced motion. `check:library` проверяет навигацию и возврат фокуса, просмотр и экспорт, сортировку, пустую папку, поиск и адаптивность 320–1920 px.

Для следующего этапа ещё нужны отдельные состояния сохранения и конфликта Markdown, перенос и удаление с отменой, восстановление доступа к источнику, устаревшие данные и пропуски в аналитике. Пока серверные операции не подключены, создание папок и демоматериалов живёт только в текущей вкладке и сбрасывается после перезагрузки.

## Источники

Референсы пользователя определяют визуальное направление. Использованы применимые принципы [taste-skill](https://github.com/Leonxlnx/taste-skill) и [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines).

Шрифты подключены локально, без CDN: Inter и Golos Text — пакеты `@fontsource-variable`, Manrope — `public/fonts`. Все под SIL OFL (`public/fonts/Manrope-OFL.txt` и лицензии в пакетах). Иконки — [Phosphor](https://phosphoricons.com); движение — Motion и CSS; диаграммы — SVG; 3D цеха — three.js и React Three Fiber.

Все участки цеха используют один материал и одинаковую толщину контуров. Telegram представлен сложенным бумажным самолётом, TikTok — объёмным вертикальным видеоплеером, материалы — раскрытой папкой с двумя листами. Это геометрические 3D-модели в общем изометрическом ракурсе, без фронтальных логотипов и текстовых значков.

Комментарии изображены единой полупрозрачной панелью с тремя сообщениями, аватарами и отступами ответов. При работе новые сообщения плавно входят снизу, старые уходят вверх; после остановки лента мягко останавливается на целой строке. Reduced motion оставляет три сообщения неподвижными. У сбора постоянно видны четыре падающих фрагмента с контурами и короткими следами: в ожидании поток медленный, при обработке ускоряется. Reduced motion оставляет фрагменты неподвижными. Иконки площадок в цехе монохромные; основной график аналитики сохраняет различимые цвета источников.

Маршруты цеха определены в `src/lab/workshop/workflow.ts`: Telegram и TikTok передают файлы сбору, далее идут комментарии, темы, материалы и аналитика. При полном демонстрационном цикле после каждого этапа пакет проходит по соответствующей линии, затем начинается следующий этап. Камера держит общий план с местом для панели. Отмена прекращает обработку и передачу; при reduced motion движение пакета заменяется статичной подсветкой маршрута. Это визуализация демонстрационного процесса, без реального сетевого обмена.

Наведение на модель или её подпись выделяет входящие и исходящие связи; тот же фокус доступен с клавиатуры. После подтверждённой передачи на входном порте появляется мягкий импульс длительностью 520 мс. Отмена не вызывает подтверждения; reduced motion заменяет расширяющееся кольцо неподвижным кратким выделением. Экранный диктор получает описание связей и уведомление о доставленном файле.

Наведение или клавиатурный фокус также проигрывает анимацию модели: движение самолёта, ленту комментариев, поток сбора, документы и столбцы. Это предварительный визуальный просмотр, который не запускает обработку, передачу файлов или смену статуса участка. Во время работы анимация продолжается независимо от положения курсора.

Кнопка «V2 · Оркестратор» включает отдельную кольцевую компоновку с центральным узлом; «V1 · Цепочка» сохраняет прежнюю схему. В V2 участки сначала обрабатывают данные и обмениваются результатами, затем семь файлов одновременно передаются в центр. Оркестратор проверяет и объединяет их в `workspace.md`. Отдельный участок передаёт в центр только свой результат. Переключение версии и остановка отменяют незавершённую работу. Это демонстрация взаимодействий, а не серверный планировщик.

## Состояния и сценарии

Блок `#scenarios` позволяет переключать три изолированные демонстрации: первый запуск без подключённых источников, успешный цикл и тайм-аут TikTok. Демоисточники подключаются кнопкой; сбор проходит этапы получения данных, анализа и сохранения. При сбое сохраняется частичный результат Telegram. Повторная попытка получает только TikTok и дополняет общий отчёт, который можно скачать в Markdown. Прочерк обозначает отсутствие данных, а не нулевое значение.

Остановка, сброс и переключение сценария отменяют незавершённые этапы. Блок не меняет данные основного цеха или графиков и не обращается к внешним сервисам. `check:scenarios` проверяет прохождение сценариев, экспорт, повторную попытку, отмену, клавиатуру, reduced motion и адаптивность.

## VPS

`Dockerfile` и `deploy/nginx.conf` остаются заготовками для размещения статической сборки. Контейнер и выпуск на VPS не выполнялись. Будущие пользовательские Markdown-файлы должны храниться вне публичной директории и выдаваться через авторизованный API.
