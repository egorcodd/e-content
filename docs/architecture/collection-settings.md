# Параметры сбора

## Назначение

Настройки описывают объём входных данных для поиска идей. Аккаунт даёт доступ, источник задаёт адрес и формат, параметры задают выборку. Назначение «Мой контент» не является доказательством владения и не открывает закрытую статистику.

## Уровни

| Уровень                 | Что хранится                                                                   | Где применяется                                    |
| ----------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| Параметры по умолчанию  | Период 7/30/90 дней, публикации, комментарии, статистика, лимиты на источник   | База Telegram и TikTok                             |
| Настройки площадки      | Только изменённые общие поля плюс особенности Telegram/TikTok                  | Ко всем источникам этой площадки                   |
| Источник                | Ссылка, формат, аккаунт, назначение, включение в сбор                          | Нормализация отдельного задания и проверка доступа |
| Ограничения запуска     | Общие пределы публикаций и комментариев; внутренний предел запросов            | Совместный бюджет всех заданий                     |
| Проверенные возможности | Доступ к конкретному источнику, метрики, ответы, фильтры, порядок комментариев | Допуск задания к исполнению                        |

У отдельного источника пока нет собственного редактора переопределений. Он получает настройки своей площадки и нормализует их по формату и доступу. Не добавляем ещё один скрытый уровень наследования до появления такого сценария.

## Наследование

`CollectionOverrides` содержит только явно изменённые поля. Отсутствие ключа означает наследование; `false` и `0` — полноценные значения. `custom: null` и пустой объект означают отсутствие переопределений. Панель площадки всегда показывает итоговые значения; изменение поля автоматически создаёт переопределение, отдельный режим редактирования не нужен.

Пример: база — 30 дней и 1000 комментариев; Telegram переопределяет только `maxComments: 250`. Если поменять базовый период на 7 дней, Telegram получит 7 дней и сохранит 250 комментариев, TikTok получит 7 дней и 1000 комментариев. Сброс поля удаляет ключ переопределения. Сброс площадки возвращает все общие поля к базе, сохраняя её специфические настройки.

Интерфейс отображает число изменённых полей; у каждого из них появляется кнопка сброса к базе. `resolveCollectionSettings` — единственное место слияния, используемое интерфейсом, проверкой конфигурации и подготовкой заданий. Проверка итогового набора запрещает отключить все три типа данных, включая конфликт после изменения базы. Неудачное сохранение не меняет конфигурацию в хранилище.

Представление разделено на `PlatformSteps` (аккаунт и адреса), `PlatformCollectionSettings` (эффективные параметры выбранной площадки) и `CommonCollectionSettings` (редко меняемая база и общий бюджет). Общая форма по умолчанию свёрнута. `SettingsDisclosure` отвечает за плавное раскрытие, клавиатурную доступность и исключение скрытых полей из фокуса. Специфические фильтры находятся в дополнительном разделе, не создают ещё один уровень наследования и не меняют бюджет запуска. Высота основной панели ограничивается компоновкой необходимых полей; жёсткая обрезка содержимого по высоте не используется.

Схема версии 2 сохраняется под прежним ключом `e-content-sources-v1`. При чтении старых полных копий настроек сохраняются отличия от текущей базы; одинаковые поля снова наследуются. Это сохраняет их текущие итоговые значения. В старом формате невозможно отличить намеренно закреплённое равное значение от автоматически скопированного. В версии 2 явное равное значение сохраняется как переопределение.

## Семантика параметров

- Период — фиксированное окно в UTC от времени запуска назад на выбранное число суток. Коннектор применяет его к дате публикации и дате комментария; отсутствие времени в ответе не означает, что дата подходит. Для отдельной ссылки также проверяется период.
- Лимит публикаций — сколько родительских постов/роликов можно рассмотреть для одного источника. Он нужен и при сборе только комментариев. Выключение типа «Публикации» отключает сохранение их текста, но не поиск родительских публикаций. Нулевой лимит публикаций отключает источник целиком.
- Один пост/ролик ограничивается одной публикацией; канал/профиль использует лимит выборки. Разрешение короткой TikTok-ссылки выполняет будущий серверный адаптер и учитывает его сетевой запрос.
- Лимит комментариев относится ко всему источнику, а не к каждому посту внутри него. Вложенные ответы входят в этот же предел. Ноль отключает комментарии и ответы, оставляя другие выбранные данные.
- Telegram: `threads` означает включение вложенных ответов; корневые комментарии всё равно читаются из обсуждения. `forwards` включает пересланные публикации; при выключении требуется метаинформация о пересылке. `minLength` фильтрует текст комментария после нормализации.
- TikTok: `replies` включает вложенные ответы; `minLikes` применяется к счётчику конкретного комментария. Без доступного счётчика нельзя молча считать его равным нулю. Порядок `platform` означает порядок ответа площадки. Старый `top` нормализуется в `platform`, не обещая сортировку по популярности; `recent` требует подтверждённой возможности адаптера.
- Фильтры текста и лайков не разрешают обходить лимиты: просмотренные записи тоже расходуют бюджет, даже если не попали в результат.
- Статистика имеет режим `public` либо `owner`, выбираемый по проверенным возможностям. Отметка назначения источника не повышает права. Подключённый аккаунт сам по себе не гарантирует доступ к приватному каналу или административной статистике.

В интерфейсе поле `metrics` называется «Счётчики»: оно запрашивает текущие доступные показатели публикаций. Этот переключатель не обещает получить исторические графики за любой выбранный период. Данные роста аудитории нужно накапливать либо получать через доступную административную аналитику; источники просмотров не доступны универсально. Период сбора и период, который возвращает API статистики, — разные вещи.

«Общий объём сбора» — ограничение e-content, а не параметр стороннего API и не лимит одной страницы ответа. Например, три источника с пределом 100 комментариев каждый дают до 300, но общий предел 200 остановит запуск на 200 суммарно. В пользовательском редакторе два предела данных; `maxRequests` сохранён во внутренней конфигурации для исполнителя и не регулируется ползунком. Он не заменяет ограничения частоты, ожидание FloodWait или backoff. Сохранение пользовательских лимитов не меняет этот технический предел.

Для соблюдения периода план требует `publicationDates` и, при сборе комментариев, `commentDates`. Если коннектор не подтверждает даты, нельзя молча принять выбор периода. Отдельная запись без даты не считается попавшей в окно; исполнитель отмечает неполноту. Особенно это важно для TikTok, где даты в нормализованной модели DTK допускают `null`, а порядок комментариев не гарантирует сортировку по времени. Сверка параметров с документацией приведена в [разборе API](../research/SOURCE-PARAMETERS.md).

## Подготовка запуска

Для цвета рассчитывается доля, которую один источник может занять в общем бюджете e-content: `min(1, значение / общий предел)`. До 80% цвет нейтральный; в последних 20% бюджета интенсивность плавно нарастает до красного. Порог 80% — настройка представления бюджета приложения, не опубликованная квота API и не гарантия безопасности аккаунта. Верхняя граница ползунка на цвет не влияет. При нулевом бюджете положительный объём подсвечивается полностью; при неизвестном бюджете и у фильтров цвет нейтрален. Сам общий бюджет не окрашивается без подтверждённого внешнего ограничения. Числовые границы формы являются ограничениями конфигурации приложения; менять их на максимальный размер страницы 35/100 было бы ошибкой. Подтверждённые числа и источники — в [исследовании ограничений](../research/COLLECTION-LIMITS.md).

`buildCollectionPlan(configuration, { at, access })` получает снимок конфигурации и результаты проверки доступа для каждого источника. В модуле нет React, хранилища, входа в аккаунт и сетевых запросов.

1. Проверяет конфигурацию и исключает отключённые источники и нулевые выборки.
2. Нормализует ссылки и формат, разрешает наследование по полям.
3. Проверяет привязку доступа к источнику, площадке и выбранному аккаунту. Повторные или неподтверждённые результаты проверки отклоняются. Идентификаторы `preview:*` не допускаются.
4. Проверяет возможности для выбранных типов данных, ответов, фильтров и сортировки. Неподдерживаемое требование возвращает причину по конкретному источнику; параметры не игнорируются молча.
5. Создаёт глубоко неизменяемый план с фиксированным окном, отдельными заданиями и общим бюджетом. Последующее редактирование настроек не изменяет этот снимок.

Результат имеет `status: ready | blocked | empty`. При `blocked` отдельные успешно подготовленные задания могут присутствовать для предварительного просмотра, но **запускать их нельзя**. Нельзя автоматически начинать частичный сбор. `empty` не создаёт сетевую работу. Предел одного задания не превышает общий бюджет, но сумма заданий может превышать его: общий бюджет должен расходоваться совместно.

## Исполнение и доверие

Сейчас реализованы конфигурация, миграция, интерфейс и подготовка плана. Исполнитель сетевого сбора и сервер коннекторов отсутствуют; цех пока проигрывает визуальный процесс. Показанные ограничения ещё не являются работающим сетевым ограничителем.

Будущий backend повторно проверяет конфигурацию, владельца аккаунтов и доступ. `SourceAccess` приходит от серверной проверки, а не принимается на доверии из браузера. Сессии и секреты не входят в план и не хранятся в `localStorage`.

Перед каждой страницей/повтором worker атомарно резервирует запрос из одного бюджета запуска. Публикации и комментарии, включая ответы и отфильтрованные записи, расходуют соответствующие общие и локальные счётчики. Повторные страницы не создают повторных идей благодаря устойчивым ID записей, но каждый сетевой повтор расходует лимит запросов. При исчерпании бюджета сохраняется частичный результат с причиной остановки; бесконечный повтор не допускается. Общий ноль комментариев не останавливает публикации; ноль публикаций или запросов не создаёт задания. Параллельные задания не получают отдельную копию общего бюджета.

После завершения или остановки закрытие панели и повторное открытие результата не создают новую задачу. Новый запуск требует отдельного явного действия. Этот документ задаёт контракт будущего исполнения; серверную часть нужно проверить отдельно после подключения реальных адаптеров.

## Проверка

`npm run check:collection-policy` проверяет наследование, нули и `false`, миграцию, разные форматы источников, доступ и возможности, бюджеты, неизменяемость снимка и атомарное сохранение. `npm run check:module-setup` проверяет изменение базы при переопределении площадки и сброс отдельного поля через интерфейс. `npm run check:sources` покрывает сохранение источников, ссылки, редактор и синхронизацию вкладок.
