# TikTok: локальный публичный коннектор

Подключение задаётся одним профилем. В разделе «Ролики для цеха» рядом со списком задаются число последних роликов и лимит комментариев на каждый ролик. Панель «Данные TikTok» задаёт тип данных и период комментариев. Это чтение публичных данных, а не OAuth и не подтверждение владения аккаунтом. Расширение Zen, профиль основного браузера и его cookies не используются.

## Реализация

`NativeTikTokSource` реализует существующий `TikTokReader`. Сервер e-content хранит выбранный профиль, настройки и результаты в SQLite. Смена страницы и закрытие панели не запускают сбор повторно. Публичный профиль хранится отдельно от прежней Zen-сессии; собранные материалы при отключении сохраняются.

`NativeTikTokHost` запускает закреплённый [MIT-сборщик sangzun-han/Tiktok-Api](https://github.com/sangzun-han/Tiktok-Api/tree/d438d72fa903aa0ecb6f104fa9b915928134fe0a) отдельным локальным процессом. Приложение обращается к его REST-интерфейсу. Подписи запросов и HTTP-транспорт остаются в upstream; его код не копируется в сервер e-content и не модифицируется. Версия и источник заданы в `collectors/tiktok/upstream.json`. Зависимости и Python-окружение устанавливаются в закрытую для Vite папку `.local`.

Установка: `npm run setup:tiktok`, затем обычный `npm run dev`. Нужны Node.js и Python с поддержкой `tarfile` extraction filters. Docker и платный сервис не требуются. Установщик использует закреплённый commit upstream и отключает npm install scripts. Первый запуск создаёт внутреннюю анонимную web-сессию; интерфейс не просит пользователя подтверждать гостевой доступ.

## Данные и ограничения

- Ролики сортируются по проверенным датам, ID сохраняются строками. Дополнительная страница уменьшает влияние старых закреплённых роликов на выбор последних N.
- Читаются тексты корневых комментариев и отдельные страницы ответов. У ответов сохраняются video ID и parent ID; совпадающие ID не дублируются.
- Счётчики просмотров, лайков, комментариев и репостов — текущие снимки. Они не предоставляют ретроспективные просмотры по дням, удержание или приватные источники трафика.
- Число последних роликов настраивается от 1 до 100, комментариев на ролик — от 1 до 10 000; по умолчанию 20 и 100. Это границы настройки приложения, не официальные квоты или подтверждённые безопасные пороги TikTok. Единственное сохранённое значение каждого поля находится в серверной настройке TikTok; в конфигурацию запуска переносится её снимок.
- Лимит на ролик включает ответы. После достижения этого лимита обработка переходит к следующему ролику. Отдельный общий лимит комментариев действует на весь запуск и также включает ответы. Общие значения «на источник Telegram» не ограничивают TikTok вторым скрытым пределом.
- Если все выбранные ролики обработаны в пределах настройки на ролик, запуск считается завершённым, даже когда на части роликов достигнут этот предел. Число таких роликов остаётся в результате. Общая остановка раньше окончания выборки и неполная выдача TikTok отмечаются отдельно как частичный результат.
- Последние N роликов выбираются независимо от давности публикации, их метаданные сохраняются. «Период комментариев» и фильтр лайков применяются к сохраняемым комментариям. Прогресс различает полученные до фильтрации и сохранённые записи.
- Причины разделены: `TIKTOK_PER_VIDEO_LIMIT`, `TIKTOK_TOTAL_COMMENT_LIMIT`, `TIKTOK_REPLIES_INCOMPLETE`, `TIKTOK_VIDEO_LIST_INCOMPLETE`, ошибки доступа и повторения курсоров. Прогресс хранит число выбранных и обработанных роликов, а новый запуск — применённые параметры и общие ограничения. Пустой ответ не считается успешным сбором нуля комментариев.
- Для ответов учитывается `total`: upstream описывает случай `has_more=0` при наличии продолжения. Если продолжение получить невозможно, результат остаётся частичным.
- Автоматические повторы после отказа и ротация аккаунтов отключены. Один логический запрос REST учитывается в лимите запросов e-content; внутренние запросы подготовки анонимной сессии upstream не являются отдельными единицами этого счётчика. Это лимит приложения, не официальная квота TikTok.
- При отмене запрос останавливается, дочерний сборщик закрывается. Уже полученные записи остаются в SQLite. Отбор идей выполняет существующий модуль цеха.

## Проверка 17 ноября 2026

TikTokApi 7.3.5 испытан первым и не допущен: два запуска вернули пустой `userInfo`, отдельный запрос комментариев — `EmptyResponseException`. Ошибка не была подменена пустым списком идей. Этот эксперимент не входит в исполняемый код приложения.

Закреплённый native-сборщик без авторизации получил у `@egorcod` 20 роликов, 29 корневых комментариев и 15 настоящих ответов двух роликов. Обезличенный исходный результат хранится локально в `.local/tiktok-native/proof.json`; тексты и авторы комментариев в документацию и журнал проверки не выводятся.

Настоящий запуск через основной API цеха `tiktok-native-live-1794934727307` сохранил один пост и 50 комментариев, включая 32 ответа; выполнено 16 логических запросов, сформировано 6 кандидатов идей. Статус — `partial`: сработал установленный предел 50, полный обход 20 роликов этим прогоном не подтверждается. Все 50 ID уникальны, ссылки и родительские связи проверены. Это результат нового транспорта, а не прежнего Zen-прототипа.

Серверные проверки отдельно проверяют сохранение профиля, отсутствие ложной авторизации аккаунта, пагинацию ответов, общий лимит, пустую выдачу и повтор курсора. Настоящий запуск через API проверяет `scripts/check-tiktok-native-live.mjs --live`; он ограничен 50 комментариями вместе с ответами и 25 логическими запросами, поэтому может закономерно завершиться частично. Тесты с подготовленными ответами и настоящий запуск различаются явно.

Один успешный прогон не доказывает длительную устойчивость. Upstream молодой и неофициальный; наблюдение за отказами и обновление закреплённой версии остаются необходимыми. Ошибка сборщика не должна сбрасывать библиотеку или переводить интерфейс к повторным входам в основной аккаунт.
