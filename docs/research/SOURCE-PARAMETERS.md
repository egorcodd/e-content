# Параметры источников: сверка с API

Проверено 16 ноября 2026 года по официальной документации Telegram/TikTok и текущим исходникам DTK. Проверка документальная: реальные аккаунты не подключены и сбор на них не выполнялся. Поля в нормализованной модели и существующий маршрут не гарантируют успешный ответ площадки в конкретном окружении.

## Что означает каждый параметр

| Параметр интерфейса                       | Что даёт API                                                                                                                                         | Что делает e-content                                                                                                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Период 7/30/90 дней                       | Telegram отдаёт историю с датами и пагинацией; DTK имеет даты публикаций и комментариев, допускающие отсутствие значения                             | Фиксирует окно запуска, фильтрует по времени. Для TikTok нельзя считать первую страницу полным результатом за период или прекращать чтение по первому старому комментарию без гарантии порядка |
| Публикации                                | История Telegram; описания и метаданные видео TikTok                                                                                                 | Сохраняет текст, описание и исходную ссылку. Видео не скачивается и не транскрибируется этим переключателем                                                                                    |
| Комментарии                               | Telegram `messages.getReplies`; у DTK отдельные маршруты корневых комментариев и ответов                                                             | Обходит доступные страницы в пределах бюджета. Тексты комментариев не являются возможностью обычного TikTok Display API                                                                        |
| Счётчики                                  | Показатели доступны в зависимости от источника и доступа. TikTok Video Object перечисляет `view_count`, `like_count`, `comment_count`, `share_count` | Сохраняет доступный текущий снимок. Отсутствующий счётчик не подменяет нулём и не превращает в исторический график                                                                             |
| Лимит публикаций/комментариев на источник | API имеет ограничения размера страницы, отличающиеся по методу и площадке                                                                            | Общий предел обхода одного канала, профиля, поста или ролика. Например, 1000 комментариев читаются несколькими страницами; нельзя передавать 1000 как размер одной страницы DTK                |
| Ответы                                    | Ветки Telegram; у DTK `/video/comments/replies` отдельно от `/video/comments`                                                                        | Включает вложенные ответы в общий счётчик комментариев источника и запуска                                                                                                                     |
| Telegram: пересланные публикации          | Telegram Message содержит необязательный `fwd_from`                                                                                                  | Фильтрует пересылки по метаданным родительского поста                                                                                                                                          |
| Telegram: длина реплики                   | Текст сообщения                                                                                                                                      | Фильтрует нормализованный текст локально; это не отдельный параметр `getReplies`                                                                                                               |
| TikTok: минимум лайков                    | В Comment DTK есть nullable `digg_count`                                                                                                             | Фильтрует полученные записи локально; неизвестное число лайков не проходит положительный порог как подтверждённое значение                                                                     |
| Общий объём сбора                         | Это не квота сторонней площадки                                                                                                                      | Совместный бюджет всех источников одного запуска. Не суммируется отдельно для каждого worker и не умножается на число каналов                                                                  |

## Ограничения, влияющие на интерфейс

**Telegram.** Для истории и веток нужен пользовательский API, доступ к каналу и обсуждению. Обычный вход на сайт через Telegram не заменяет эту сессию. Детальная аналитика канала зависит от прав администратора и `can_view_stats`; период сводки возвращает Telegram, он не обязательно совпадает с выбранными в приложении 7/30/90 днями. Рост аудитории и источники просмотров нельзя обещать для любого чужого канала. [История](https://core.telegram.org/method/messages.getHistory.md), [ветки](https://core.telegram.org/method/messages.getReplies.md), [статистика](https://core.telegram.org/api/stats).

**TikTok.** Display API включает профиль, список и метаданные видео. Официальное чтение текстов комментариев описано отдельно в Research API и требует соответствующего доступа; авторизация своего профиля в Display API не добавляет его автоматически. Для MVP рассматривается отдельный self-hosted DTK-адаптер, который ещё нужно проверить на своих роликах. [Display API](https://developers.tiktok.com/docs/en/display-api-overview), [Research Comments](https://developers.tiktok.com/docs/en/research-api-specs-query-video-comments).

У текущего DTK TikTok-страница ограничена 35 записями в соответствии с проверкой маршрута. `sort=new` для TikTok отклоняется; ответы запрашиваются отдельно. `created_at` и `digg_count` в модели Comment допускают `null`. Поэтому интерфейс не предлагает неподтверждённую сортировку, а подготовка задания требует подтверждения дат, фильтров и ответов у конкретного адаптера. Версию DTK перед интеграцией следует зафиксировать; `main` меняется. [Маршруты](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/src/dtk/api/routes/content.py), [модели](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/src/dtk/models/content.py).

## Что оставлено внутренним

Технический предел запросов, размер страницы, число повторов, ожидания и обработка FloodWait/backoff относятся к исполнителю. Ползунок «Запросов за запуск» удалён из пользовательской формы: его число не равно числу публикаций и не равно числу комментариев. Один вызов может вернуть страницу, ответы требуют дополнительных вызовов, DTK также использует задачи с ожиданием результата. Старое значение `maxRequests` сохраняется в конфигурации, чтобы изменение интерфейса не сбрасывало ограничитель.

Всё это пока контракт подготовки и будущего исполнения. Работа лимитов во время реального сетевого сбора должна быть проверена после реализации backend/worker; нынешняя анимация цеха не является такой проверкой.
