# История аналитики TikTok без входа в аккаунт

Проверено 18 ноября 2026 года.

## Что подтверждено

Публичный коннектор e-content получает профиль по имени и читает список его публичных роликов, который TikTok показывает веб-посетителю. Подключение означает выбор профиля для сбора. Коннектор открывает собственную анонимную веб-сессию и получает дату публикации и текущие счётчики просмотров, лайков, комментариев и репостов. Число подписчиков берётся из ответа профиля. Пароль, OAuth-токен владельца и cookies из его браузера для этого не используются. [Устройство коннектора](../architecture/tiktok-native.md) · [Парсер роликов](../../server/tiktok/parser.ts) · [Закреплённая версия MIT-сборщика](https://github.com/sangzun-han/Tiktok-Api/tree/d438d72fa903aa0ecb6f104fa9b915928134fe0a)

Список поддерживает постраничное чтение. Поле `hasMore` сообщает, есть ли продолжение, а `cursor` указывает следующую страницу. При полном обходе @egorcod 18 ноября 2026 года получена 61 уникальная публичная публикация. Самая ранняя датирована 4 ноября 2025 года. Это замер накопленных счётчиков на дату обхода. Официальный Display API также выдаёт публичные ролики страницами и возвращает текущие счётчики, при этом требует авторизацию пользователя. [Сбор каталога](../../server/analytics.ts) · [Display API](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list) · [Поля ролика](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-object)

**Дата публикации и дата замера отвечают на разные вопросы.** Публичная выдача позволяет показать, какие ролики и месяцы публикации набрали больше просмотров к текущему моменту. Чтобы узнать, сколько просмотров весь профиль получил в конкретный прошлый день, нужны счётчики, сохранённые тогда, или отчёт с дневной разбивкой. Один текущий счётчик не содержит распределения просмотров по дням. В Research API период относится к датам публикаций, а счётчики в архивной выдаче могут обновляться с задержкой. В опубликованной схеме Data Portability есть дата поста, полученные лайки и число подписчиков, а история просмотров описывает ролики, которые смотрел пользователь. Ряда полученных просмотров по дням в этой схеме нет. [Research API](https://developers.tiktok.com/docs/en/research-api-get-started) · [FAQ Research API](https://developers.tiktok.com/docs/en/research-api-faq) · [Поля Data Portability](https://developers.tiktok.com/docs/en/data-portability-data-types)

## Открытые инструменты и ограничения

- **sangzun-han/Tiktok-Api** уже установлен в e-content. Он умеет листать публичные ролики профиля и возвращает их текущие метрики. Это прямой кандидат для прохода по всему публичному каталогу. [Документация сборщика](https://github.com/sangzun-han/Tiktok-Api#paging)
- **yt-dlp** извлекает дату и накопленные показатели отдельных роликов. **TikTokApi** от David Teather тоже читает публичные данные через браузерную сессию, однако предыдущая локальная проверка на этом проекте вернула пустые ответы. Эти инструменты не содержат архива датированных замеров @egorcod. [Парсер yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/tiktok.py) · [TikTokApi](https://github.com/davidteather/TikTok-Api) · [Локальная проверка](../architecture/tiktok-native.md)
- **tiktok-stats-tracker** под MIT показывает подход с регулярным сохранением счётчиков и вычислением изменений из двух последовательных замеров. Он начинает накопление с первого собственного сбора. [Репозиторий трекера](https://github.com/Iliesseu28/tiktok-stats-tracker)

## История до первого замера

**TikTok Studio доступен авторам с личным аккаунтом.** Владелец входит в свой TikTok и открывает аналитику аккаунта в приложении или на сайте TikTok Studio. В ранней инструкции TikTok описан экспорт аналитики с компьютера. Варианты Studio в приложении и на сайте могут отличаться. Для импорта исторических просмотров в e-content нужен отчёт с датой и числом просмотров публикаций за каждый день. Доступный диапазон и колонки выгрузки именно для @egorcod пока не проверены. [Типы аккаунтов TikTok](https://support.tiktok.com/en/using-tiktok/growing-your-audience/switching-to-a-creator-or-business-account) · [TikTok Studio](https://newsroom.tiktok.com/helping-creators-bring-creativity-to-life-with-tiktok-studio?lang=en) · [Описание экспорта TikTok Analytics](https://newsroom.tiktok.com/product-tutorial-tiktok-analytics/?lang=en)

TikTok for Business также описывает Accounts Insights для авторизованных аккаунтов. Для получения доступа разработчику нужно подать заявку на разрешение TikTok Accounts. Этот доступ в e-content не подключён. [Accounts API](https://business-api.tiktok.com/portal/docs/accounts-api-overview/v1.3)

## Что имеет смысл реализовать в e-content

Аналитика обходит весь доступный публичный каталог и показывает текущие итоги, список публикаций с даты выхода самого раннего доступного ролика и дату проверки. Цех использует заданное число последних роликов для чтения комментариев и отбора идей. Для динамики счётчики сохраняются регулярно по каждому ID ролика. Изменение между замерами считается по сопоставимым данным, а при пропусках показывается интервал между доступными замерами. Неполный обход хранит проверенное покрытие и не выдаётся за результат полного профиля.

Наличие открытого источника с готовой историей ежедневных просмотров именно для @egorcod до первого замера не подтверждено.

## Повторная проверка Display API, 20 ноября 2026 года

Для Display API TikTok требует одобрить приложение и получить согласие владельца. С разрешением `video.list` можно обойти публичный каталог страницами до 20 роликов или запросить до 20 уже известных ID владельца. Дата в курсоре списка ограничивает время **публикации**. Запрос по ID вернёт текущие счётчики ролика. В этих двух методах нет параметра «значение на дату». [Подключение](https://developers.tiktok.com/docs/en/display-api-get-started) · [Список](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list) · [Запрос по ID](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-query) · [Поля ролика](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-object)

На уровне профиля разрешение `user.info.stats` даёт число подписчиков, подписок, лайков и публичных видео. Суммарных просмотров и разбивки по дням в списке полей нет. Для расчёта через Display API цеху по-прежнему понадобились бы собственные замеры. [Поля профиля и разрешения](https://developers.tiktok.com/docs/en/tiktok-api-v2-get-user-info)

Для расчёта прироста следует сопоставлять ролики по ID. Например, исчезновение ролика с миллионом просмотров уменьшит сумму каталога на миллион и исказит разность двух сумм. В отчёте за интервал стоит отдельно учитывать общий для обоих замеров набор, новые публикации и исчезнувшие ID. Дату первого появления старого ролика в каталоге нельзя использовать как дату получения всех его просмотров.
